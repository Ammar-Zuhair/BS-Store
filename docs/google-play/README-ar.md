# تجهيز Google Play وبناء Android App Bundle

تاريخ المراجعة: 7 أكتوبر 2026.

## بناء ملفات AAB من GitHub Actions

أُضيف سير العمل `.github/workflows/android-production-aabs.yml`. يبني محلياً على عامل GitHub باستخدام `eas build --local`، لذلك لا يستهلك دقائق EAS Build السحابية. لا يرفع التطبيق إلى Google Play تلقائياً.

قبل أول تشغيل، أضف في مستودع GitHub ضمن **Settings → Secrets and variables → Actions** السر التالي:

| الاسم        | الغرض                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| `EXPO_TOKEN` | مصادقة Expo/EAS حتى يستطيع البناء التحقق من المشاريع وتنزيل بيانات توقيع Android المحفوظة في حساب Expo. |

لا تضع مفاتيح R2 أو أسرار الخادم في GitHub Actions أو التطبيق؛ لا يحتاجها بناء الواجهات. احتفظ بها في أسرار الخادم كما هي.

لتشغيل البناء: افتح **Actions → Build Android production AABs → Run workflow**، واختر `all` أو تطبيقاً واحداً. ينشئ التشغيل حزمة تنزيل باسم `production-aabs-<run number>` وبداخلها ملف لكل تطبيق تم اختياره:

- `customer-app.aab` — `com.bsstore.customer`
- `admin-app.aab` — `com.bsstore.admin`
- `courier-app.aab` — `com.bsstore.courier`

الإعدادات الحالية في التطبيقات الثلاثة هي `version 1.0.1` وملف `production-aab` من نوع `app-bundle`، ومصدر رقم إصدار Android مضبوط على EAS. احفظ سجلّ التوقيع نفسه لكل تحديث لاحق، ولا تستبدل مفتاح الرفع الذي تقبله Google Play.

### متطلبات البيئة

- حساب Expo الذي يملك المشاريع الثلاثة، ورمز `EXPO_TOKEN` بصلاحية الوصول إليها.
- بيانات اعتماد توقيع Android محفوظة في EAS للمشاريع؛ يتطلب البناء المحلي تنزيلها عبر الرمز.
- متغيرات بيئة `production` التي يحتاجها `app.config.js` (خصوصاً `EXPO_PUBLIC_API_URL`) متاحة للبناء. توثيق Expo يذكر أن متغيرات EAS ذات مستوى الرؤية **Secret** غير مدعومة في البناء المحلي؛ اجعل متغيرات `EXPO_PUBLIC_*` المطلوبة متاحة للبناء محلياً في GitHub Actions أو غيّر مستوى ظهورها في بيئة Expo إلى `Sensitive` عند كونها بيانات مضمّنة في التطبيق أصلاً. قيم `EXPO_PUBLIC_*` تظهر داخل حزمة التطبيق ولا تصلح كأسرار.
- احتفظ بعنوان API ثابتاً يعمل عبر HTTPS قبل الإطلاق العام؛ لا تعتمد على رابط نفق مؤقت.

سير العمل يثبّت Node 22 وJava 17 وAndroid SDK 36 وNDK/CMake، ويبني كل تطبيق بالملف `production-aab`، ثم يرفع ملفات AAB كـ GitHub Artifact لمدة 14 يوماً. بعد تنزيل الحزمة، ارفع AAB العميل أولاً إلى مسار اختبار داخلي في Play Console وجرّبه على أجهزة فعلية قبل الإصدار العام.

تفاصيل صفحة المتجر هنا تخص تطبيق العميل العام. التطبيقان الإداري وتطبيق الموصل أدوات تشغيلية، ويمكن بناء AAB لهما من سير العمل نفسه؛ إن أردت نشرهما للجمهور فلكل منهما صفحة متجر وبيانات مراجعة وسياسة خصوصية وتعليمات وصول منفصلة. لا يعني بناء ملفهما أنهما جاهزان للنشر العام.

## ما يلزم في Play Console

### صفحة المتجر

مسودة الاسم والوصف العربي في [customer-listing-ar.md](./customer-listing-ar.md). يلزم استكمال:

- بريد دعم يمكن للمستخدمين الوصول إليه، واسم المطوّر المطابق لحساب Play.
- رابط HTTPS عام لسياسة خصوصية تخص BS Store، متاح دون تسجيل دخول أو حجب جغرافي، مع رابط أو نص سياسة ظاهر داخل التطبيق.
- مسار واضح داخل التطبيق لطلب حذف الحساب، ورابط ويب عام صالح لطلب حذف الحساب وبياناته. تطبيق العميل يسمح بإنشاء حساب، ولم أجد حالياً مسار حذف حساب أو endpoint له؛ هذا شرط إطلاق يجب إنجازه قبل النشر.
- أيقونة المتجر منفصلة بمقاس 512×512، PNG ‏32-bit مع alpha، أقل من أو يساوي 1MB.
- صورة feature graphic بمقاس 1024×500، JPEG أو PNG ‏24-bit بلا alpha.
- لقطتا شاشة على الأقل من التطبيق الفعلي للنشر، ويفضل أربع لقطات هاتف واضحة بدقة لا تقل عن 1080×1920. لا تستخدم صوراً مصطنعة أو واجهات تختلف عن الإصدار الذي سيُراجع.
- فيديو معاينة اختياري.

### إفصاحات ومراجعة Google

أنشئ سياسة المحتوى، تصنيف المحتوى العمري، الفئة، الجمهور المستهدف، وإقرار وجود الإعلانات داخل Play Console. راجع خصوصاً ما إذا كانت عروض المتاجر المدفوعة تُعد إعلانات في التطبيق.

أكمل نموذج **Data safety** وفق سلوك التطبيق والخادم ومزودي الخدمات معاً، لا وفق أذونات Android فقط. عناصر ينبغي تدقيقها قبل تعبئة النموذج: الاسم ورقم الهاتف، كلمة المرور/بيانات المصادقة، عنوان التوصيل وموقعه، الطلبات وسجل الشراء، إيصالات التحويل المصورة، رموز الإشعارات، وأي بيانات قياس/تشخيص ترسلها مكتبة Boosthis أو غيرها. تحقق من تدفق الصور إلى R2، والإشعارات عبر Expo/Firebase، وأي سجلات أو نسخ احتياطية في الخادم. لا تعتبر هذه القائمة إقراراً نهائياً؛ الناشر مسؤول عن صحة الإفصاح.

أضف إلى تعليمات المراجعة حساب عميل تجريبي فعال وبيانات دخول وطريقة وصول إذا كانت شاشات التطبيق تتطلب حساباً. لا تستخدم بيانات حساب المدير الحقيقي. راجع نموذج الميزات المالية بصدق: التطبيق يقبل مدفوعات لطلبات المتجر عبر النقد أو التحويل وإيصال التحويل؛ لا تصفه بخدمة مصرفية أو تحويل أموال إن لم يكن كذلك.

إن كان حساب Play الشخصي أُنشئ بعد 13 نوفمبر 2023، فقبل طلب النشر العام يلزم اختبار مغلق مع 12 مختبراً على الأقل ظلوا منضمين 14 يوماً متصلة، ثم طلب صلاحية الإنتاج.
