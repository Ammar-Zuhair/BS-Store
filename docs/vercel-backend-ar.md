# تجهيز Vercel

إعدادات النشر موجودة في مستودع الـ backend المستقل:

- [دليل النشر والخطوات والأوامر](../backend/deployment/README.ar.md).
- [إعداد Container والعامل المستمر](../backend/vercel.json).
- [Dockerfile الخاص بـ Vercel](../backend/Dockerfile.vercel).

ملف البيئة الخاص مولّد في `/workspace/backend/deployment/.env.vercel`، ومستثنى من Git وDocker ومن الملفات المرسلة عبر Vercel CLI. استورده في Production بعد تحديد رابط الإنتاج في `APP_PUBLIC_URL` و`App__BaseUrl` بدون `/api`.

لم تُغيّر روابط التطبيقات ولم يُنشر تحديث Expo لهذا النقل؛ ينفذ ذلك بعد تزويدنا برابط الإنتاج والتحقق منه. رابط التطبيقات يحتوي `/api`، ويمكن إرساله عبر Expo Updates إلى runtimes المدعومة دون بناء أصلي جديد.

العامل المستمر مفعّل بنسخة واحدة من أول نشر إنتاجي للحفاظ على توزيع الطلبات والإشعارات والرسائل الجماعية والتنظيف. يمكن البدء بخطة Hobby ثم الترقية عند الحاجة. حصة الذاكرة تُستهلك طوال تشغيل العامل حتى مع صفر مستخدمين؛ الاستخدام ليس مرتبطاً بعدد المستخدمين وحده. عند التأكد من تشغيله على Vercel، نسّق إيقاف عمال السيرفر القديم مع إبقاء API القديم متاحاً للتطبيقات. تفاصيل الحصص وحد حجم الطلب ومراجع الصور القديمة موضحة في الدليل.
