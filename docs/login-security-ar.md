# تسجيل الدخول وحماية المحاولات

يجمع تطبيق العميل رقم الهاتف وكلمة المرور في شاشة واحدة ويرسل طلباً واحداً إلى `POST /api/auth/login` مع الدور `Customer`. لا يستدعي فحص وجود الرقم. لا تُقص المسافات من كلمة المرور، ويُمنع الإرسال المتكرر أثناء الطلب. عند الرد `429` يعرض التطبيق الوقت المتبقي ويعطل الدخول حتى انقضائه.

الخادم يسمح بخمس محاولات دخول لكل عنوان IP، وتشمل المحاولات الناجحة والفاشلة وجميع أدوار التطبيقات. عند الخامسة يبدأ حظر مدته 60 ثانية كاملة؛ السادسة وما بعدها ترفض قبل الوصول إلى قاعدة البيانات أو فحص كلمة المرور. الرد يحتوي `Retry-After` و`retryAfterSeconds`. إعادة المحاولة أثناء الحظر لا تطيل المدة. إن لم تكتمل خمس محاولات خلال الدقيقة يعاد ضبط العداد. تعمل العدادات في ذاكرة نسخة الخادم الحالية وتُصفّر عند إعادة التشغيل؛ تشغيل نسخ خادم متعددة يستلزم عداداً مشتركاً قبل التوسع.

لا يعرض الخادم اختلافاً في حالة HTTP أو رسالة الخطأ بين رقم غير مسجل وكلمة مرور خاطئة. يفحص تجزئة وهمية للرقم غير المسجل لتجنب الاستجابة السريعة دون تكلفة فحص كلمة المرور. مسار `check-phone` القديم يبقى لتوافق التطبيقات السابقة: يرجع `exists: true` لجميع الأرقام دون قراءة قاعدة البيانات، لتنتقل تلك التطبيقات إلى إدخال كلمة المرور. النتيجة ليست دليلاً على وجود الحساب.

يقبل الخادم رأس عنوان العميل المحوّل من نفق ngrok المحلي فقط، ويقرأ آخر قفزة واحدة. لا يثق برؤوس العناوين الآتية مباشرة من مصادر أخرى. يبقى الحد العام للـ API فعالاً بالإضافة إلى حد الدخول.

الروابط الرسمية المستخدمة في العميل ومصادر صفحات الويب:

- [سياسة الخصوصية](https://ammar-zuhair.github.io/BS-Store-Policy/)
- [حذف الحساب](https://ammar-zuhair.github.io/BS-Store-Delete/)

التحقق: `node tests/customer-login.cjs` لاختبار الشاشة، و`node tests/customer-login-api.cjs` لاختبار إرسال الطلب وقراءة مدة الحظر من الرأس أو JSON، و`node tests/account-and-image-drafts.cjs` لاختبار روابط الحساب، و`node tests/receipts/run.cjs` لاختبار الخادم المعزول، بما فيه تساوي أخطاء الدخول والطلبات المتزامنة والحظر لمدة دقيقة واستعادة الدخول وعزل عناوين العملاء ورفض انتحال رؤوس العنوان.
